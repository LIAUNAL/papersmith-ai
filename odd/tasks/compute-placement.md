# Compute placement: choose local or cloud, CPU or GPU, loader and data form by measurement, never by default

Objective: before a proof of concept or a full experiment runs, smith measures the candidate ways to run it (local CPU with N processes, local MPS/GPU, each Kaggle/Colab account and its machine, CPU-only remote included) and the data path (batch size, loader workers, prefetch, cached representation), then recommends the fastest affordable plan with account parallelism; a GPU is never chosen without evidence.
Branch: `feat/compute-placement` (from `origin/main` b40171fc, v0.37.0). Delivery: release after verification. Tests: `~/Documents/papers_smith/papersmith-ai/.micromamba/envs/papersmith/bin/python -m pytest -q -n 6`; `npm test`.

## Specs

- S0. The operator's request, verbatim (2026-10-29): "el segunde es referente a la prueba de concepto y experimentos, a la hora de revisar si se corre en local o en nube, y con que esquema, solo cpu o gpu, asegurate de verififcar qe la corrida por gpu no sea el defecto, verifica costos en prefetching, particiones de lotes,  etc, y busca la mejor alternativa, incluso si con cpu. verifica tambien si puede ser viable aprovechar la cache o formas de representacion de los datos para que la carga y proceso sea mas eficiente, y busca siempre la mejor alternativa posible, aprovechando paralelizacino en distintas cuentas tambien de colab o kaggle si estan dispoinibles"
- S1. Candidate-aware timing record (schema 2, schema 1 still read): each measurement may carry `candidate` (e.g. `local-cpu-4`, `local-mps`, `kaggle:<owner>/T4`, `colab:<owner>/T4`, `colab:<owner>/cpu`), `threads`, `processes`, `batchSize`, `numWorkers`, `pinMemory`, `prefetch`, `dtype`, `dataSource` (`raw|cached`), `loadSeconds`, `computeSeconds`; the record carries host info (`cpuCount`, `ramGB`, `mps`, `cuda`). The `mixed-devices` refusal is keyed by candidate, so one host may hold CPU and GPU rows without pooling them.
- S2. Kit probe (`proposal-implementation/assets/kit/nb/`): a bounded sweep (time-capped per candidate) over device, batch size, loader workers, pin memory/prefetch and CPU thread count that splits load time from compute time and writes S1 rows. It never picks a device itself; device selection in the kit has no GPU-first default (no evidence -> no choice, CPU stays a first-class candidate).
- S3. Data-representation advice: when loading dominates (load share above a stated threshold), the plan recommends a cached preprocessed form (float32 tensors, `.npy` memmap, precomputed windows) with the measured share as evidence; advice only, no data rewritten.
- S4. A read-only `plan` verb in `remote-parallelism` (`parallelism_cli.py plan`): over every measured candidate (local CPU multi-process, local accelerator, each Kaggle and Colab account of the team, CPU-only remote), combines estimate, placement limits and assess/schedule account parallelism; outputs the recommended placement + device + batch/loader settings + account split with makespan, quota/cost and the reason each other candidate lost; unmeasured candidates are listed as `unmeasured` with the probe or rehearsal that would measure them, never extrapolated; a GPU candidate wins only if measured faster or cheaper.
- S5. Remote honesty: `generate-job --accelerator-kind cpu` creates a CPU-only remote job on services that support it (refused clearly where not); the adapters' GPU default stays for compatibility but `preflight`'s `accelerator` row says the GPU was a default, not a measured choice, and points to `plan`; `session-fit` reads the candidate's own row.
- S6. Dashboard run options show one row per candidate (measured or unmeasured) and the plan's recommended pick with its reason.
- S7. Doctrine: proposal-implementation and experimental-implementation SKILLs, the walk/build agents and the remote-parallelism SKILL require running the probe and `plan` before choosing placement for a PoC or a full experiment, comparing CPU vs GPU and local vs cloud including local multi-process and multi-account parallelism; doctrine files name no service.
- S8. Docs, help text, CHANGELOG `## Unreleased`.

# Plausibility thematic help from banco-lia, and the flow, README, docs and dashboard brought up to date

Objective: in the phase-2 (plausibility) box of the dashboard, an operator without a clear idea can open "Ayuda temática", type 3 to 5 keywords, have the server query the banco-lia MCP, see the best-matching LIA items and topics with a proposed `/plausibility` prompt, edit and approve it, and launch it as the phase-2 prompt; then the Archify flow, the README, its linked docs, its figure and the dashboard reflect every flow update (thematic help, Novedad & Hallazgos panel and G-NOVELTY from 0.45.0, the 0.44.0 results discussion and phase 5 gating).

## Specs

- S0. The operator's request, verbatim: L1.
- S1. **banco-lia client** `skills/_core/command_center/banco_suggest.py` (stdlib only): a minimal MCP stdio JSON-RPC client that starts the SAME server command papersmith registers for agents (`uvx --from git+https://github.com/LIAUNAL/bancoProyectosPapersLIA banco-lia-mcp`, read from the workspace `.mcp.json` `mcpServers["banco-lia"]` when present, else that default), performs `initialize` + `notifications/initialized`, then `tools/call` `search_bank` (and `taxonomy` for topic names), with a bounded timeout (first `uvx` run may download: allow ~90 s, configurable), always terminating the child process. Overridable command through env `PAPERSMITH_BANCO_LIA_COMMAND` (JSON argv list) for tests and offline clones. Never raises to the caller: unavailable (`uvx` absent, spawn failure, timeout, protocol error) returns `{"available": false, "reason": "<one line>"}`.
- S2. **suggest(keywords, language)**: accepts 3 to 5 keywords (each trimmed, non-empty, at most 40 chars, deduplicated case-insensitively); otherwise a typed refusal `KEYWORDS_INVALID` naming the rule. Queries `search_bank` with `match="all"` first and falls back to `match="any"` when it returns fewer than 3 items; returns `{"available": true, "keywords": [...], "match": "all"|"any", "items": [{"id","kind","title","year","cluster","doi","score","snippet"}] (at most 8, best first), "topics": [{"id","name","count"}] (topics/clusters of the returned items, most frequent first, at most 5), "draft": "<proposed plausibility idea>"}`. The draft is composed deterministically from the keywords and the matched items (no model call, no invented data): at least two sentences (so `/plausibility`'s two-sentence rule holds), in the dashboard language (`es` default, `en`), naming the keywords, the strongest topic(s) and 1-3 LIA items as continuity context (projects H*/P* as background, articles by title/DOI), and ending with what the idea would test. When nothing matches, `items` is empty and the draft still states the keywords as an idea to explore, with a note that the bank holds no related work.
- S3. **Endpoint** `POST /api/plausibility/suggest` in `server.py`: JSON body `{"keywords": [...], "language": "es"|"en"}`; same-origin enforced like the other POST routes (`origin_is_same`), 403 otherwise; 422 with the refusal for invalid keywords; 200 with S2's body (including `available: false` cases). It never writes to the workspace.
- S4. **UI** (`static/phase-console.js`, `phase_actions.py`, i18n): the plausibility prompt card gains a collapsible "Ayuda temática (palabras clave)" / "Thematic help (keywords)" block: 3 to 5 keyword inputs (3 shown, "+" up to 5), a "Proponer idea" button (disabled until 3 valid keywords), a loading state, then the ranked items (title, kind, year, score, DOI link when present), the topics, and the draft in an editable textarea; buttons "Aprobar y lanzar" (copies the edited draft into the card's prompt input and runs the existing `runPrompt` launch path, so `/plausibility <draft>` goes through the same agent selector, sentence check and run tracking) and "Descartar". `available:false` shows the reason and the hint to install `uv`/check `.mcp.json` (docs/mcp.md). Nothing is launched without the operator's click. Escape everything. `phase_actions.py` marks the plausibility action with `keyword_help: True` and its guide mentions the help. Spanish and English catalogue keys with parity (`tests/test_dashboard_i18n.py`); server strings in `server-es.json`.
- S5. **Phase-2 description** in `server.py` (`desc` of Fase 2, and a sub-phase `2.0`-style detail is NOT added -- no on-disk evidence) mentions the optional thematic help from banco-lia.
- S6. **Skill doctrine** `skills/plausibility/SKILL.md`: an operator may arrive with a draft composed by the dashboard's thematic help; it is an idea like any other (two sentences minimum still applies; the bank items are LIA continuity context, never SOTA evidence and never cited as such).
- S7. **Archify flow** (`docs/diagrams/papersmith-pi-flow.build.mjs` → regenerated `papersmith-pi-flow.html` + `papersmith-pi-flow.png` per `docs/diagrams/README.md`, Archify 3.0.1 at `~/.claude/skills/archify/bin/archify.mjs`, `finalize` must pass; `skills/_core/command_center/static/papersmith-flow.html` byte-identical copy; `docs/diagrams/locales/es.json` for any new label): draws the thematic help (keywords → banco-lia → proposed prompt → `/plausibility`), the novelty assessment (Novedad & Hallazgos panel, G-NOVELTY gate, `smith novelty`) where it sits in the flow, and the results discussion (`Results/discussion.json`, gating 5.8/5.11) at the proof-of-concept and full-experiment stretches, within the readability gates the README describes; `meta.repository.revision` and node `sources` updated. `docs/diagrams/README.md` updated if the structure description changes.

# Paper-type lines: identify the paper type after plausibility, adapt flow and dashboard, add empirical lines

Objective: make plausibility general, add a paper-type identification step (deterministic match score + advisor agent, agreed with the operator) and a "Paper type" dashboard panel before Concept Map & Model; let the agreed type drive the workspace layout, flow and dashboard; give the review line its own board; then add lines for empirical, laboratory, computational, data-resource and composite-index papers. The applied-AI flow stays as it is.
Branch: one branch per task (`feat/paper-type-*`), chained PRs. Delivery: ask-on-risk. Tests: `.micromamba/envs/papersmith/bin/python -m pytest -q -n 8 --dist loadfile` (full suite before any merge that adds a skill or agent); `npm test`.

## Specs

- S0. The operator's requests, verbatim: L1-L6. Status: planned, not implemented.
- S1. Applied-AI flow unchanged (L3 "asegurate de que el flujo base ia quede como, esta"; interpretation agreed in L6): phases, gates, phase cards, skills and agents of the `experimental` line keep their behaviour. The only change an `experimental` workspace may show is additive and declared: the paper-type sub-step at the end of Phase 2 and the Paper type panel. A workspace without `.papersmith/paper_type.json` is `experimental` and the sub-step is advisory (locks nothing). A characterization test pins, byte for byte, `/api/status`, `phase_actions` output, the harness flow text and `kit_layout` for an `experimental` workspace before any refactor; it accepts only the declared additive diff.
- S2. Paper-type catalogue, one source of truth (`paper_types` registry, data): per type an id, a name and a one-or-two-line summary (English; the dashboard's Spanish lives in its i18n catalogue), where its novelty lies, its stages, its reporting guidelines, the signals that indicate it, its line and a status `available` | `planned`; a type may group variants (name, summary, guidelines, signals) that share its flow and choose its checklist. The agent, the panel, the plausibility skill and the docs read it. Catalogue agreed in L21 (eight types):
  1. applied-ai (method vs SOTA; available, line `experimental`);
  2. review (systematic, scoping, bibliometric; available, line `review`, PRISMA 2020);
  3. observational-measurement, variants observational (STROBE, CROSS), diagnostic-validation (STARD, TRIPOD+AI), measurement-instrument (indices, scales, questionnaires; COSMIN);
  4. experiment-intervention, variants human-trial (CONSORT 2025, SPIRIT; ethics, consent, registration) and field-experiment (plots, blocks, crops, animals; ARRIVE 2.0, in-house agronomy checklist);
  5. qualitative-participatory, variants qualitative-mixed (SRQR, COREQ, GRAMMS), consensus-foresight (Delphi, MICMAC, MACTOR, scenarios, practice guidelines; AGREE II) and experience-report (teaching innovation, programme description);
  6. hardware (device, sensor or instrument build and validation: HardwareX template, GUM, Bland-Altman/ICC, TRL);
  7. lab-simulation, variants materials (process-property studies) and modelling-simulation (simulation or analytical models), sharing GUM-style uncertainty;
  8. data-resource (corpus, dataset or benchmark as the contribution).

  - new panels reading `review/*.json(l)` and `review_cli.py status`: protocol and registration, search log, screening progress (pending, conflicts, kappa), PRISMA flow, extraction table, risk of bias, PRISMA 27-item checklist.
- S7. Shared empirical machinery (L1): study-protocol deliberation (a third deliberation-engine profile: question, primary outcome, design, sample size, analysis plan, locked like G-PROTOCOL); ethics and registration gate recorded by the operator; data dictionary and QC on own data (reusing `datasets` qc/license); analysis log of every analysis run, exploratory analyses labelled, manuscript diffed against the protocol (guards against p-hacking, HARKing, outcome switching); checklist engine generalizing the PRISMA checklist that checks item content, not presence; participant flow diagram generator (CONSORT, STROBE, STARD); final-judge rubric per line; measurement core (uncertainty, replicates, instrument metadata, raw-data traceability) shared by hardware and lab-simulation; fact vocabulary and `FACT_SOURCE_ROOT` entries for protocol, sample, outcomes, analysis plan, participant flow.
- S8. New lines, in order: observational-measurement; hardware and lab-simulation (sharing the measurement core); data-resource; experiment-intervention; qualitative-participatory. Each line is a kind (contract set `sections-<kind>/`, flow template, skill, checklist, gates) following the review line's packaging; the assistant never generates measurements or data, and ethics, consent, data collection and the choice of primary outcome stay human.

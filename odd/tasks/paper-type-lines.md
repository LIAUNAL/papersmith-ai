# Paper-type lines: identify the paper type after plausibility, adapt flow and dashboard, add empirical lines

Objective: make plausibility general, add a paper-type identification step (deterministic match score + advisor agent, agreed with the operator) and a "Paper type" dashboard panel before Concept Map & Model; let the agreed type drive the workspace layout, flow and dashboard; give the review line its own board; then add lines for empirical, laboratory, computational, data-resource and composite-index papers. The applied-AI flow stays as it is.
Branch: one branch per task (`feat/paper-type-*`), chained PRs. Delivery: ask-on-risk. Tests: `.micromamba/envs/papersmith/bin/python -m pytest -q -n 8 --dist loadfile` (full suite before any merge that adds a skill or agent); `npm test`.

## Specs

- S0. The operator's requests, verbatim: L1-L6. Status: planned, not implemented.
- S1. Applied-AI flow unchanged (L3 "asegurate de que el flujo base ia quede como, esta"; interpretation agreed in L6): phases, gates, phase cards, skills and agents of the `experimental` line keep their behaviour. The only change an `experimental` workspace may show is additive and declared: the paper-type sub-step at the end of Phase 2 and the Paper type panel. A workspace without `.papersmith/paper_type.json` is `experimental` and the sub-step is advisory (locks nothing). A characterization test pins, byte for byte, `/api/status`, `phase_actions` output, the harness flow text and `kit_layout` for an `experimental` workspace before any refactor; it accepts only the declared additive diff.
- S2. Paper-type catalogue, one source of truth (`paper_types` registry, data): per type an id, a name and a one-or-two-line description (English and Spanish), the signals that indicate it, its reporting guideline, the lines it maps to, and a status `available` | `planned`. The agent, the panel, the plausibility skill and the docs read it. Initial catalogue (evidence in L7-L11):
  1. applied-ai (method vs SOTA; exists, `experimental`);
  2. review (systematic, narrative, bibliometric; exists, `review`, PRISMA 2020);
  3. observational (survey, cohort, cross-sectional, econometric/spatial on own or secondary data; STROBE, STROBE-Vet, CROSS);
  4. intervention (clinical, educational, field/agronomic, consumer experiments; CONSORT 2025, SPIRIT 2025, CONSORT-SPI, REFLECT, ARRIVE 2.0; agronomy needs an in-house checklist);
  5. qualitative-mixed (case study, participatory, foresight; SRQR, COREQ, GRAMMS);
  6. diagnostic-validation (diagnostic accuracy, prediction, clinical validation of a measure across sites/languages; STARD, TRIPOD+AI);
  7. lab-measurement (hardware/instrument build and validation: HardwareX template, GUM uncertainty, Bland-Altman/ICC, TRL; materials process-property studies);
  8. computational (simulation and modelling: model definition, calibration against known values, protocol, parametric sweep, statistical error, code and data release);
  9. data-resource (corpus, dataset or benchmark as the contribution);
  10. composite-index (indices or policy instruments built with stakeholders, robustness, institutional adoption).
  Minor types kept out of the first catalogue: case report (CARE), clinical practice guideline (GRADE, extends review), position paper.
- S3. Paper-type identification at the end of plausibility (L3 "plausability sea general, y en esa iteracion un agente sugiera que tipo de paper consteuir para discutir con el usuario y ser parte de la iteracion"; L5 "una fase que identifique el tipo de paper"):
  - a deterministic match score per type (0-100, no model call, same pattern as `prompt_gate.py`) from the idea text and plausibility artifacts (claim grades, SOTA families, atlas slots, the candidate pool);
  - a `paper-type-advisor` agent and a `/paper-type` skill that refine the scores with reasons, discuss the type with the operator and propose one; the novelty-screener is not modified;
  - the decision persisted in `.papersmith/paper_type.json` `{scores:[{type, score, why, signals}], suggested, agreed, by, at, pool_sha256}`; the plausibility acceptance is persisted too (today it lives only in the conversation);
  - plausibility made general: the atlas `topic_ai` slot and AI-specific wording depend on the type, `experimental` keeping today's behaviour exactly.
- S4. Paper type panel in the dashboard, placed before Concept Map & Model (L5 "un panel en smith ui, antes de concept map y math que presente el score o mathc para el tipo d paper y una descripcion corta y concisa pero relevante de cada tipo de paper trabajado en smith y su relacion o no con la idea trabajada hasta esa fase de palusibilidad y tipo de paper"): one card per catalogue type with name, short description, score bar, reporting guideline, availability, and one sentence relating the type to the idea (why it fits or not, citing its signals); the suggested and agreed types highlighted; "Discuss with the agent" and "Agree type" (confirmation, then `smith kind set`); a planned type says so and names the closest available line. Spanish and English keys with parity.
- S5. `smith kind set <type> --by <name>`: records the agreed type, re-applies the kit layout through `upgrade`, removes the other kind's contracts only when unedited (hash matches the manifest), reports edited ones as stranded, refuses once `proposals/*-r*.md` or `paper/main.tex` exists unless forced, regenerates the harness flow text. Fixes the existing defect that `smith upgrade` overwrites operator-edited `sections/` contracts.
- S6. Per-type dashboard, review first (L3 "para el flujo reiview mira que debemos cambiar o ajustar en el tablero ui para que quede acorde a ese tipo de manuscrito"): the board reads the type once (`api_status_adapter` → `phase_actions.attach`); for `review`:
  - fix: `state_extractor.SECTION_ORDER` and `paper_preview` show 9 experimental contracts as missing; `SECTION_METADATA` collides by stem; `PHASE_GATES` locks Scaffolding on G-NOVELTY forever; EVIDENCE globs, gates list, telemetry labels, AI-history stages and agents view are experimental;
  - adapt: Pipeline (the 10 review steps, G-PROTOCOL, screening sign-off, synthesis accepted), Archify flow (own diagram), Sections, Artifacts (`review/*`), AI history, telemetry, agents table, final judge (PRISMA/AMSTAR-style rubric instead of the ML-conference rubric);
  - hide: Concept Map & Model, Experiments, Novelty & Findings, SOTA constellation;
  - new panels reading `review/*.json(l)` and `review_cli.py status`: protocol and registration, search log, screening progress (pending, conflicts, kappa), PRISMA flow, extraction table, risk of bias, PRISMA 27-item checklist.
- S7. Shared empirical machinery (L1): study-protocol deliberation (a third deliberation-engine profile: question, primary outcome, design, sample size, analysis plan, locked like G-PROTOCOL); ethics and registration gate recorded by the operator; data dictionary and QC on own data (reusing `datasets` qc/license); analysis log of every analysis run, exploratory analyses labelled, manuscript diffed against the protocol (guards against p-hacking, HARKing, outcome switching); checklist engine generalizing the PRISMA checklist that checks item content, not presence; participant flow diagram generator (CONSORT, STROBE, STARD); final-judge rubric per line; measurement core (uncertainty, replicates, instrument metadata, raw-data traceability) shared by lab-measurement and computational; fact vocabulary and `FACT_SOURCE_ROOT` entries for protocol, sample, outcomes, analysis plan, participant flow.
- S8. New lines, in order: observational; lab-measurement and computational (sharing the measurement core); data-resource; intervention; qualitative-mixed; diagnostic-validation; composite-index; then the minor types. Each line is a kind (contract set `sections-<kind>/`, flow template, skill, checklist, gates) following the review line's packaging; the assistant never generates measurements or data, and ethics, consent, data collection and the choice of primary outcome stay human.

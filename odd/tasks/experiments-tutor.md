# Experiments tutor: consult and iterate on experiment decisions from the experiments panel

Objective: a read-only tutor in the dashboard's experiments panel, built on the math tutor's machinery, that explains, questions and evaluates the experiment design and its implementation, and hands any change of decision to `/experimental-deliberation`.
Branch: `feat/experiments-tutor` (from `origin/main` b40171fc, v0.37.0). Delivery: release after verification. Tests: `~/Documents/papers_smith/papersmith-ai/.micromamba/envs/papersmith/bin/python -m pytest -q -n 6`; `npm test`.

## Specs

- S0. The operator's request, verbatim (2026-10-29): "en el panel e experimentos, agrega otro tutor, como el de mapa de cocepto y matematica, donde se pueda consultar e iterar respecto a las decisiones de los experimeintos, incluyendo arquitectura de las redes, hyperparametros, estudios de ablacion, pruebas de significancia estadistica, proposito del experimetno toy set, estrategias de entrenamietno, techos, metodos a comparar y su implementacion, y lo que consideres prudente para guiar, evaluar y entender mejor dichas implementaciones."
- S1. A new read-only skill and agent `experiments-tutor` (canonical `skills/experiments-tutor/SKILL.md`, `.claude/agents/experiments-tutor.md`; tools `Read, Glob, Grep` only; mirrors generated by `scripts/sync-repo-harness.py`). Its doctrine covers, as decision areas the tutor can explain, question and evaluate: network architecture; hyperparameters and the hyperparameter search; ablation studies; statistical significance tests; the purpose of the toy-set experiment; training strategies; ceilings ("techos", upper bounds and oracle/reference results); the methods to compare (baselines) and the fidelity of their implementation; plus validation scheme and leakage, compute budget and session fit, and reproducibility. It grounds every claim in workspace evidence it read (paths), never invents measured numbers ("nothing measured yet" when there are none), never reads credential stores or `.remote-execution` secrets, and never edits files: a change of decision is drafted as an instruction for `/experimental-deliberation`, where the human gate lives.
- S2. Backend: `tutor.py` is generalized to a profile (thread folder, agent and skill files, context builder, turn schema, modes) with the math tutor's behavior and its `/api/terminal/tutor/*` contract unchanged; each profile has its own lock. The experiments profile builds a size-capped digest from `experiments_view` (protocol of the latest experiments version, per product: kind, significance, HPO summaries, table headers, timing, run counts, diagrams; datasets registry) plus the paths of `Experimental_AGREED.md`, `AGREED.md` and the target `src/` for the agent to read; thread at `.papersmith/experiments-tutor/thread.json`.
- S3. Turn schema for the experiments tutor: `reply`, `question` (one per turn), `assessment{level 0-4, label, evidence, gaps}`, `next_step`, `decision_area` (one of the S1 areas or `general`), `evidence` (paths read), `risks`, `deliberation_prompt` (draft instruction for `/experimental-deliberation`, or empty). Modes `ask`, `explain`, `evaluate`.
- S4. Routes `/api/terminal/tutor/experiments/thread` (GET, DELETE) and `/api/terminal/tutor/experiments/turn` (POST) behind the same `_terminal_refusal` guards (terminal cookie, same origin); timeout -> 504, invalid turn -> 422.
- S5. UI: a tutor card in `#pane-experiments`, outside `#experimentsRoot`, in a new `static/experiments-tutor.js` with its own cache-busted script tag; Spanish UI copy; a decision-area selector with the S1 areas; renders the thread with the existing rich-text helper; a "Deliberar este cambio" button that sends `deliberation_prompt` to `/experimental-deliberation` through the existing CLI send path; reset button.
- S6. Registries, flow docs (paper-flow template), README, CHANGELOG `## Unreleased`, help text updated; harness projections in sync.

# Prompt quality gate: measure every phase prompt, alert, propose an improvement or ask, then launch on approval

Objective: every prompt a phase skill receives is scored against a rubric drawn from published prompt-engineering guidance; a prompt under the threshold or with a critical failure raises an alert with an improved prompt for approval, or clarifying questions when the input is too thin, and launches only on the operator's approval. Works in the agent terminal, the dashboard phase cards and the embedded smith terminal of the UI, for claude, pi, opencode and agy.
Branch: `feat/prompt-quality-gate` (from `main`). Delivery: ask-on-risk; local work-unit commits only (push/PR/release are the user's decision). Tests: `.micromamba/envs/papersmith/bin/python -m pytest -q <files>`; `npm test` for node.

## Specs

- S0. The operator's requests, verbatim: L1, L2.
- S1. Architecture chosen by the operator (L3, "Híbrido (Recomendado)"): a deterministic per-phase score (no model, instant) on every surface, plus an LLM gate inside each phase skill's entry where the agent itself evaluates, asks when inputs are missing, proposes the improved prompt and waits for approval. In the dashboard phase cards, when the score falls under the threshold or there is a critical failure, a headless reviewer shows the alert with the suggestion or the questions before launching. Extra LLM cost only when the prompt is bad.
- S2. Deterministic scorer `skills/_core/command_center/prompt_gate.py` (stdlib only): `check(skill, text)` returns score 0-100, threshold, verdict `pass`/`fail`, and issues with severity `critical`/`major`/`minor`, from a generic rubric (empty, too short, vague, leftover example placeholder) and a per-skill input contract (what each phase skill needs: e.g. two sentences with problem and proposal for `/plausibility`, a path or URL for `/paper-ingestion`, a figure id for `/figure-review`). Fails on a critical issue or a score under the threshold. CLI: `python -m skills._core.command_center.prompt_gate check --skill <name> [--text <t>]` (stdin when no `--text`), one JSON object on stdout.
- S3. In-agent gate for terminal and embedded terminal: the slash command body (`command.md.tpl`, projected to `.claude/commands`, `.opencode/commands`, `.pi/prompts`) and the Antigravity rules (`antigravity-rules.md.tpl`, agy reads skills without command files) make the agent apply the gate doctrine (`skills/_core/command_center/prompt_gate.md`) to `$ARGUMENTS` before following the skill: run the scorer; on fail "propone una mejora y muestra alerta al usuario indicando que el prompt no es claro y le muestra su sugerencia de mejora y le pide si la aprueba para vilverlo a lanzar"; when it lacks inputs, "le presenta unas preguntas o decisiones interactivas para buscar aclarar el prompt, lo construye y lo lanza mejirado". Approval marker or an explicit "launch as is" skips the gate.
- S4. Prompt reviewer agent `.claude/agents/prompt-reviewer.md` (projected to the other three runtimes) and dashboard endpoints: `POST /api/prompt/check` (deterministic) and `POST /api/prompt/review` (headless reviewer through `tutor.run_agent`, claude → agy → pi; returns `improve` with an improved prompt and the user's preserved requirements, or `clarify` with questions and options; with answers it composes the improved prompt). Same-origin enforced; never writes to the workspace.
- S5. Dashboard phase cards (`static/phase-console.js`): "deberia medirse la calidad del prompt en cada fase" — every launch of a prompt card is scored; under threshold or critical: alert that the prompt is not clear, the suggested improvement in an editable box, "Approve and launch", "Launch as is", "Cancel"; or the questions with options, then the prompt built from the answers launches ("lo construye y lo lanza mejirado"). Nothing launches without the operator's click. Spanish and English keys with parity.
- S6. Docs and help: the gate is described where the phase flow and dashboard are documented; CHANGELOG entry.

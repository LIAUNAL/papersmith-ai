# Validate an experiment diagram from the agent chat

Objective: the operator can validate a product's experiment diagram (`poc` / `experiments`) by approving it in the conversation with an agent (Claude Code, OpenCode, Pi, or the dashboard's CLI assistant), not only with the dashboard's "Validar diagrama" button; the launch gate keeps reading one record.
Branch: `feat/chat-diagram-validation` (from `origin/main` cc0c2657, v0.33.0). Delivery: release 0.34.0 after verification (the operator asked to adjust the flow and then continue). Tests: `~/Documents/papers_smith/papersmith-ai/.micromamba/envs/papersmith/bin/python -m pytest -q -n 6`; `npm test`.

## Specs

- S0. The operator's request, verbatim (2026-10-28): "ajusta el flujo de smith para que la validacion tambien pueda ser por el chat con el agente o desde aqui. luego valida los dos diagramad y sigue"
- S1. A `validate` verb in `skills/experiment-diagrams/scripts/diagram_cli.py`: `validate --target <repo> --name <Name> --kind poc|experiments --png-sha256 <hex> --operator-statement "<the operator's words, verbatim>"`. It writes `<Name>/diagrams/<kind>.validated.json` in the same shape the dashboard writes (so `submit`'s `DIAGRAM_NOT_VALIDATED` check and the panel read it unchanged), plus provenance fields: `via` (`"chat"` here, the dashboard's own value unchanged or `"dashboard"` if it has none — do not change what the dashboard currently writes unless needed for compatibility), `statement` (verbatim, non-empty), and the time.
- S2. It validates the image the operator saw: `--png-sha256` (full hex, or a prefix of at least 12 hex characters) must match the current PNG's SHA-256; a mismatch, a missing PNG/spec, a kind whose approval marker is absent, or an empty statement refuses with typed codes and writes nothing. `render` keeps dropping the record (a re-drawn diagram must be validated again), whichever way it was validated.
- S3. Doctrine: the skill's SKILL.md, its "What this skill never does" section, and every agent or skill text that says an agent never validates a diagram are updated to: an agent runs `validate` only after the operator explicitly approves that diagram in the current conversation, passing the operator's words verbatim and the PNG hash it showed; never on its own initiative, never inferred from silence or from an approval of something else. The dashboard button stays. Update any test that pins "offers no command that validates".
- S4. The dashboard's Experimentos panel and the "Antes de lanzar" notice keep working with a chat-validated record and show how it was validated (e.g. "validado por chat"), using the existing panel code paths; status (`diagram_cli.py status`) reports `validated` and the provenance.
- S5. Docs and help: SKILL.md usage and refusal table, CLAUDE.md-generated text if the kit projects it (regenerate projections the repository's way), CHANGELOG `## Unreleased`.

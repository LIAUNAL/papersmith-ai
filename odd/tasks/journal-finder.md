# Journal finder and venue adaptation, from the PDF preview panel

Objective: from the dashboard's PDF Preview tab, the operator chooses a quartile range (any contiguous range within Q1-Q4) and gets a ranked list of journals that publish work like this paper, each with its SJR quartile (or a clearly labelled OpenAlex proxy when no SJR file was provided), open-access state, APC, h-index and the similar works that justify the fit; an agent can then read the journals' aims and scope and write a recommendation. Nothing is ever submitted.
Branch: `feat/journal-finder` (from `main` after the CI-green fix). Delivery: release 0.47.0, merge, push, delete branches and worktrees, GitHub release, update local `smith` (pipx) and QMLEEG. Tests: `.micromamba/envs/papersmith/bin/python -m pytest -q -n 6`; `npm test`.

## Specs

- S0. The operator's request and decision, verbatim: L1, L2.
- S1. **Skill** `skills/journal-finder/SKILL.md` (top-level, so it projects as `/journal-finder` through `scripts/sync-repo-harness.py`), with valid frontmatter, its objective flow, inputs, refusals table and "what this skill never does" (never submits, never contacts an editor, never invents a quartile, impact factor, APC or acceptance rate, never presents the proxy as SJR). Usage: `/journal-finder Q1-Q2 [--oa-only] [--max-apc <usd>] [--limit N]`. The agent runs the CLI (S2), then reads each shortlisted journal's aims-and-scope page (web) and writes `paper/journal-candidates.md`: per journal, why it fits (quoting the paper and the similar works), scope risks, OA/APC, quartile source; it never changes the ranking numbers the CLI produced.
- S2. **CLI** `skills/journal-finder/scripts/journal_cli.py` (stdlib only, `urllib`, one JSON object on stdout, typed refusals `{"ok": false, "error": CODE, "message"}` with non-zero exit; nothing written on refusal). Verbs:
  - `search --workspace <dir> --quartiles <range> [--oa-only] [--max-apc N] [--limit N (default 15, max 50)] [--sjr <csv>]`: `<range>` is `Q1`, `Q2-Q3`, `Q1-Q4`… (case-insensitive, a single quartile or an ascending contiguous range; else `QUARTILE_RANGE_INVALID`). Paper profile from `paper/main.tex` (`\title`, `abstract` environment, `\keywords`/keywords block) falling back to the rendered `sections/` abstract and title; `PAPER_ABSENT` when no title and no abstract can be read. Topical fit from OpenAlex: search works with the title+abstract terms (and keywords), keep `primary_location.source` of `type == journal` only, aggregate per source: similar-works count, up to 3 example works (title, year, DOI); then fetch each source (`/sources/<id>`) for display_name, issn_l, issn, publisher (host_organization_name), is_oa, is_in_doaj, apc_usd, homepage_url, summary_stats (h_index, 2yr_mean_citedness), main topic field. Fit score = normalized similar-works count (documented formula). Quartile: SJR when an SJR CSV is available (S3), matched by any ISSN (normalized, no hyphens): best quartile + per-category quartiles + SJR value + year; else **proxy**: percentile of 2yr_mean_citedness among OpenAlex journals of the same field (two count queries per source), mapped to Q1..Q4 and labelled `quartile_source: "openalex-proxy"`. Filter to the range, apply `--oa-only` / `--max-apc`, rank by fit score, write `paper/journal-candidates.json` (schema 1: `generated_at`, `query` {title, keywords, terms}, `quartiles`, `filters`, `quartile_source_summary`, `sjr` {file, year} | null, `candidates` [...], `excluded_count`, `notes`). A polite `mailto` / User-Agent per OpenAlex etiquette from `PAPERSMITH_CONTACT_EMAIL` when set (never hard-coded). Bounded: request timeout, total deadline, max works fetched, retries with backoff on 429/5xx; `NETWORK_UNAVAILABLE` when OpenAlex cannot be reached. Env `PAPERSMITH_OPENALEX_URL` overrides the base URL (tests use a local fake HTTP server).
  - `sjr-import --file <path> [--year YYYY]`: validates a SCImago "Download data" CSV (semicolon or comma delimited, decimal commas, header names matched case-insensitively: Title, Issn, SJR, SJR Best Quartile, Categories, Publisher; `SJR_FILE_INVALID` otherwise) and stores it as `~/.cache/papersmith/sjr/scimagojr-<year>.csv` (year from the file name or `--year`); prints rows, year, path.
  - `status --workspace <dir>`: the current `paper/journal-candidates.json` summary and the SJR file in use (or none).
- S3. **SJR source**: scimagojr.com sits behind a Cloudflare browser challenge, so the forge never scrapes it. The operator downloads the CSV once from https://www.scimagojr.com/journalrank.php ("Download data") and imports it (CLI `sjr-import` or the panel's upload, S5). The latest imported year is used; a file older than two years adds a note.
- S4. **Endpoints** in `server.py` (same-origin on POST, contained paths, never raising): `GET /api/journals` (the candidates file, or empty with the SJR state), `POST /api/journals/search` (body `{quartiles, oa_only, max_apc, limit}`; runs the CLI search in a worker thread with a deadline; 422 for an invalid range; returns the CLI JSON), `POST /api/journals/sjr` (multipart or raw CSV upload, size cap, runs `sjr-import`).
- S5. **PDF Preview panel UI** (`static/index.html` pane-preview and a new `static/journals-panel.js`, i18n es/en with parity): a "Revistas sugeridas" / "Suggested journals" block with two quartile selects (from Q? to Q?), OA-only checkbox, max APC input, limit; buttons "Buscar revistas" (runs `POST /api/journals/search`, loading state) and "Analizar con agente" (sends `/journal-finder <range> [flags]` through the existing CLI console `window.sendToCli`, like the phase cards); an SJR state line (file + year, or "sin archivo SJR: cuartil aproximado OpenAlex" with the download link and an upload button); the results table (journal with homepage link, quartile badge + source, SJR/proxy value, OA/DOAJ, APC, h-index, fit score, similar works expandable with DOI links), and a link to `paper/journal-candidates.md` when the agent wrote it. Everything escaped.
- S6. **Doctrine and docs**: `skills/paper-writing/SKILL.md` (venue choice happens before final formatting; point to `/journal-finder`), `docs/skills.md`, `docs/cli.md` (the endpoints and the panel), `README.md` (skills list/count, dashboard tabs table row for PDF Preview), CHANGELOG `## 0.47.0`; projections regenerated by `scripts/sync-repo-harness.py`.
- S8. **Review-time estimate per journal** (L4): `search` adds `review_time` to each candidate, computed from public article histories of the journal's recent research articles (default sample: the latest 40 articles of the last 3 years): days from `received` to `accepted` (and `accepted` to `first_online`/`epublish` when present). Source chain: (1) Crossref `/journals/<issn>/works` `assertion` entries `received`/`accepted`/`first_online` (deposited by Springer Nature and others); (2) PubMed E-utilities (`esearch` by ISSN `[is]`/`[ta]`, then `esummary` `history` `received`/`accepted`/`epublish`), honouring NCBI etiquette (`tool=papersmith`, `email` from `PAPERSMITH_CONTACT_EMAIL` when set, at most 3 requests/s, `NCBI_API_KEY` when set); (3) none. Shape: `{median_days, p25_days, p75_days, n, accept_to_online_median_days, source: "crossref"|"pubmed"|"none", window: {from, to}}`; fewer than 5 dated articles reads as `source: "none"` with `n` kept. It is labelled an estimate of submission-to-acceptance (it includes revision rounds; it is not time to first decision). The panel shows it per row (median and IQR in weeks, n, source badge; "sin datos públicos" otherwise) and can sort by it; `--max-review-days N` (and a panel input) filters out journals whose median exceeds N while keeping those without data, flagged. The agent (S1) may add the journal's own declared time to first decision from its website into `paper/journal-candidates.md` only with the page URL, labelled "declared by the journal", never overwriting the computed estimate. Env `PAPERSMITH_CROSSREF_URL` and `PAPERSMITH_PUBMED_URL` override the base URLs (tests use fakes); network failures for this step degrade to `source: "none"` with a note, never failing the search.
- S9. **Venue adaptation lives in `paper-writing`** (L6, L7): a `venue` verb group in `skills/paper-writing/scripts/` (new module `paper_venue.py`, wired into `paper_cli.py`'s parser, `REFUSAL_CLASSIFICATION`, the verb count/wording in SKILL.md and the front-door coverage test) and one agent `.claude/agents/venue-adapter.md` (tools `Read, Glob, Grep, WebFetch, WebSearch`; it writes nothing itself; projected by `scripts/sync-repo-harness.py`; registered wherever agents are pinned: `tests/test_papersmith_generators.py` AGENT_NAMES, `health_inspector.py` REQUIRED_AGENTS/SKILL_GATES, `state_extractor.py` agent-to-stage map, README/docs agent tables). Everything for one venue lives under `paper/venues/<slug>/`; the canonical `paper/main.tex` and `sections/` are never written by any venue verb.
- S10. **Verbs** (each one JSON object, typed refusals, nothing written on refusal):
  - `venue select --slug <s> (--candidate <openalex source id from paper/journal-candidates.json> | --journal "<name>" --issn <issn>)` writes `venue.json` (journal name, ISSNs, publisher, homepage, quartile and source, review-time estimate copied from the candidates file, selected_at). `VENUE_SLUG_INVALID`, `CANDIDATE_UNKNOWN`.
  - `venue requirements --slug <s> --file <json>` validates and stores `requirements.json` written by the agent (schema 1): `guidelines_urls` (non-empty), `document_class` {name, options, source: "texlive"|"publisher-template"|"generic"}, `sections` [{id (mapped to a smith section id or `new:<name>`), title, required, order}], `limits` {abstract_words {min,max}, keywords {min,max}, title_words, main_text_words, pages, figures, tables, references}, `declarations_required` [author-contributions|funding|data-availability|conflicts|ethics|acknowledgments|code-availability|...], `reference_style` {bst or description}, `extras` [highlights|graphical-abstract|cover-letter|...]; every requirement carries `quote` and `url` (refuses `REQUIREMENT_UNSOURCED` otherwise). `REQUIREMENTS_INVALID`.
  - `venue acquire --slug <s> (--texlive <class> | --file <zip/cls> --url <origin>)` records the template: for a class present in TeX Live (`kpsewhich`: elsarticle, IEEEtran, llncs, article...) only its name and the resolved path; for a publisher template, copies it into `paper/venues/<slug>/template/` with origin URL, sha256 and date (`TEMPLATE_ABSENT`, `TEMPLATE_UNSAFE` for archive path traversal, size cap).
  - `venue diff --slug <s>` writes `audit.json`: compares smith's section contracts (`sections/NN-*.md` headers: ids, order; the `**Extent**` prose ranges parsed best-effort, `undecidable` when unparseable) and the current `main.tex` (blocks written, declarations, keyword count, abstract/title word counts measured from the written blocks, the document class line) against `requirements.json`. Findings: `missing-section`, `extra-section`, `out-of-order`, `over-limit`, `under-limit`, `missing-declaration`, `class-mismatch`, `reference-style-mismatch`, `missing-extra`, `undecidable`; each with severity (blocker|major|minor), smith side, venue side (with its quote/url), and the affected block ids.
  - `venue plan --slug <s> --file <md>` stores the agent's adjustment plan `plan.md` (refuses when no audit exists or the plan references no finding id) and resets any previous approval; `venue approve --slug <s> --statement "<operator's words verbatim>" --plan-sha256 <hex>` records `approval.json` (like the diagram validation: the plan's hash must match the current plan, statement non-empty; `PLAN_HASH_MISMATCH`, `STATEMENT_EMPTY`); the dashboard button writes the same record with `via: dashboard`.
  - `venue build --slug <s>` assembles `paper/venues/<slug>/main.tex`: the venue class and preamble (from the recorded template or class), front matter mapped from the canonical blocks/declarations (title, abstract, keywords, author roles, funding, data availability...), the canonical block bodies transposed in the venue's section order, the bibliography with the venue style; refuses `PLAN_NOT_APPROVED` while blocker findings exist without an approved plan; never edits a canonical block. `venue status --slug <s>` / `venue list` summarise the state machine: selected -> requirements -> template -> audited -> planned -> approved -> built (-> compiled).
- S11. **Text changes** the plan calls for (shortening the abstract, adding a data-availability statement, renaming/merging sections...) are applied only through the existing `write` loop (redactor -> contract-auditor -> `write --draft --audit`), one block at a time, after the approval; a section the venue needs and smith lacks is proposed as a plan item that the operator decides, never invented. The agent re-runs `venue diff` after each applied item and reports the remaining findings.
- S12. **Compile**: `server.py`'s paper compile gains a venue target (`POST /api/paper/compile?venue=<slug>` or equivalent) running the same pdflatex/bibtex sequence in `paper/venues/<slug>/` under the same lock; `/api/pdf?venue=<slug>` serves `paper/venues/<slug>/main.pdf`.
- S13. **PDF Preview panel, venue part**: each journal row gains "Elegir esta revista" (runs `venue select`); a "Revista elegida" card shows the state machine with the next action: "Analizar plantilla con agente" (sends to the agent CLI: read guidelines -> `venue requirements` -> `venue acquire` -> `venue diff` -> `venue plan`), the audit findings table (severity badges, smith vs venue with quote/url links), the plan rendered with "Aprobar plan" (statement textarea + approve, hash-bound) and "Pedir cambios" (sends the operator's note to the agent to revise the plan), "Aplicar plan con agente" (sends `/paper-writing` apply instructions referencing the approved plan), "Construir y compilar versión de la revista", and a toggle to preview the canonical PDF or the venue PDF. Escaped, i18n es/en parity.
- S14. **Agent doctrine** (`venue-adapter.md` and SKILL.md venue section): read the author guidelines and the template; never invent a requirement (each with quote+url); alert on sections to adjust, missing sections and inconsistencies between smith's base template and the venue's; propose the plan only when prudent (no plan when the audit is clean except class/preamble); iterate the plan with the operator until approved; never apply text changes itself; never submit.
- S15. **Tests** for S9-S14: every verb's success and refusal paths with exit codes and nothing written on refusal, the diff findings on fixture contracts/requirements, the build output (class line, front matter mapping, canonical blocks unchanged byte for byte, canonical main.tex untouched), approval hash binding, the compile venue path (mocked toolchain), panel render (es) and escaping, agent registration tests.
- S7. **Tests** (including S8: median/IQR arithmetic, date parsing of both sources' formats, chain fallback, the <5 threshold, the filter keeping no-data journals flagged, rate limiting of PubMed calls): CLI unit tests against a fake OpenAlex HTTP server and a fixture SJR CSV (range parsing, profile extraction, journal-only filter, aggregation, SJR match by any ISSN, proxy labelling, filters, ranking, caps, refusals with exit codes and nothing written, network failure, 429 retry); endpoint tests (403 cross-origin, 422, upload cap); panel render tests under node (es), escaping; skill frontmatter/harness projection tests already in the suite stay green.

Let collaborators use the host's Caztor from their browser, sharing projects but each with a private chat and their own AI subscriptions.
Branch: feat/collaborators, based on feat/pi-provider (not merged yet). Delivery: one slice per task, each high risk, each verified. Test runner: `npx vitest run`, `npx tsc -b`, `e2e/`.

## Specs

- S1: "que se comparta todo menos las sesiones de los agentes, que cada persona trabaje con su cuenta". Projects, files, compile and settings are shared. Chat history, agent sessions, provider and model choice, auth modes, API keys and logins are per person.
- S2: "como podemos hacer para que ellos inicien sesion pero no deban descargar nada?". Collaborators use only a browser. The host on the local machine keeps working as today. Changed by L14: "para compartir fuera el link y una clave aleatoria generada para ingresar, que el usuario que comparte elija cuanto tiempo dura esa clave". An invite is a link that only opens a sign-in form plus a random access key; the host picks the key's lifetime (1 hour, 1 day, 7 days, 30 days or a date, 10 minutes to 365 days); the key signs in several browsers until it expires, and its sessions end with it; the host can revoke one key or the person; 10 wrong keys lock an invite.
- S3: "se puede hacer un tipo de sesion privada en el equipo quee esté funcionando como local?". Each collaborator gets a private folder on the host, used as HOME and as every CLI's config folder (CLAUDE_CONFIG_DIR, CODEX_HOME, XDG_* for opencode, PI_CODING_AGENT_DIR, HOME for agy), so logins never mix with the host's or each other's.
- S4: user answer "Suscripciones desde ya". Collaborators sign in to their subscriptions from the browser in v1. Method per CLI, from the map: claude `auth login` URL plus pasted code; opencode and codex device code; pi `/login` and agy through a PTY (`script -q -c`), relayed as a line-based web terminal. agy runs without D-Bus so its login lands in a file, not the host keyring.
- S5 (assumption, security): a collaborator's turns and logins run inside bubblewrap: project read-write, their private folder read-write as HOME, CLI binaries and system folders read-only, network on, the host's home hidden. Without bwrap, collaborator turns are refused.
- S6 (assumption, exposure): the server can bind beyond loopback with an explicit host and an allowlist of names (for Tailscale, the recommended way). Collaborators never receive the host's launch token. Nothing is exposed unless the host turns it on.
- S7 (assumption): one turn at a time per project, whoever runs it; others see that someone else's turn is running.
